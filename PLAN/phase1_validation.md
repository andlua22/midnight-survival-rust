# Фаза 1 — журнал перевірки

Дата: 2026-11-07. Середовище: Linux x86_64, Rust/Cargo 1.99.1.

## Підтверджено

- Cargo розпізнає всі чотири пакети та їхні цілі через `cargo metadata --no-deps`.
- Кореневий `Cargo.lock` сформовано. Узгоджені версії: Bevy 0.17.3, bevy_egui 0.38.1, bevy_rapier3d 0.32.0, egui 0.33.3, rapier3d 0.31.0.
- `cargo fmt --all --check` пройшов; окремий набір перевірок також відформатований.
- `cargo clippy --offline --workspace --all-targets -- -D warnings` пройшов.
- `cargo test --offline --workspace`: **29 тестів пройшли** — 19 у client_core та 10 у shared. Серед них реальні тести Rapier для підлоги/стіни, сходів і стрибка та CPU-тест геометрії всіх віджетів egui.
- `cargo run --locked --offline -p server -- --ticks 120` пройшов: `ticks=120 position=-0.000,0.920,12.000 grounded=true`.
- Окремий граф залежностей `server` не містить `bevy_render`, `bevy_winit`, `bevy_pbr` або `wgpu`.
- Linux-бінарник клієнта зібрано; `--help` успішно завершується без запуску Vulkan.
- Користувач підтвердив ручний графічний запуск: клієнт працює, частота кадрів приблизно **90 FPS**. Режим збірки, GPU, роздільність і VSync для цього результату не зафіксовані.
- Виробничі незалежні модулі: **25 тестів пройшли**, Clippy з `-D warnings` пройшов.
- Тести охоплюють споживання одноразового вводу, нормалізацію діагоналі, стрибок лише із землі, різну частоту кадрів, усі пресети/прив’язки, роздільність/DPI, скасування й збереження HUD, пошкоджені/часткові файли та помилки файлових операцій.
- Окремий Vulkan-пробник зібрано й запущено. Він коректно завершується з кодом 1 та повідомленням про недоступний драйвер.

## Не підтверджено

Для збірки використано доступні кешовані гілки. Новіший сумісний набір Bevy 0.20.1 / bevy_egui 0.43.1 / bevy_rapier3d 0.37.0 відомий з індексу, але пакети не кешовані, а мережеве звернення до реєстру повертає `Could not resolve host: index.crates.io`. Правило «найновіший стабільний набір» замінено явним фіксуванням доступного й перевіреного набору; міграція на новіший стек не виконана.

Під час автоматизованої перевірки `vulkaninfo --summary` повертав `ERROR_INCOMPATIBLE_DRIVER`. Команда `cargo run --locked --offline -p client_runner -- --config-dir .local` успішно збирала бінарник, після чого клієнт завершувався з кодом 1: `Vulkan не може створити instance: Unable to find a Vulkan driver`. Пробник повертав ту саму причину. Подальший успішний запуск підтверджено ручною перевіркою користувача.

Запуск вікна підтверджено користувачем. Залишаються незафіксованими контрольний release-замір із середнім FPS і p95/p99 та результати детальних перевірок взаємодії, перелічених нижче. Орієнтовні 90 FPS є вихідною оцінкою продуктивності; ціль 120 FPS не блокує прототип.

## Завершення перевірки з доступними залежностями та Vulkan

1. Для переходу на найновіший стек потрібні його пакети, оновлення lockfile та повторні перевірки сумісності API. Поточна перевірена реалізація використовує версії, наведені вище.
2. Забезпечити робочий `vulkaninfo --summary` у графічній Linux-сесії.
3. Запустити клієнт у X11 та Wayland-сеансах; перевірити журнал Vulkan/GPU, освітлення, тіні й відсутність помилок валідації графіки.
4. На полігоні перевірити стіну перед точкою появи, сходи зліва, зелений схил 20°, червоний схил 55° та низьку стелю справа. Персонаж має стояти на підлозі, не проходити крізь перешкоди, підніматися сходами й завершувати стрибок після удару об стелю.
5. Відкрити меню й редактор під час руху; керування оглядом і команди руху мають припинитися, фізична симуляція продовжується. Перевірити втрату фокуса із затиснутими WASD/Space та повернення через «Грати» без повторного стрибка чи ривка миші.
6. Для всіх 11 віджетів перевірити перетягування, прив’язки, межі масштабу/прозорості, видимість і всі чотири пресети. Зменшити вікно, змінити DPI й повернути попередній розмір: віджети мають залишатися доступними.
7. У тимчасовому `--config-dir` перевірити «Зберегти», перезапуск, «Скасувати», Escape, пошкоджений JSON і недоступний шлях запису. Помилка запису має залишати чернетку відкритою; скасування має відновлювати останній збережений стан.
8. Виконати release-замір на RTX 4060 за README. Зберегти JSON із фактичними умовами, середнім FPS і p95/p99; за результатом нижче 120 FPS сформулювати окрему задачу оптимізації.

Статус: **код зібрано й автоматично перевірено; ручний запуск підтверджено користувачем (~90 FPS)**. Контрольний замір і детальне графічне приймання ще не задокументовані.
